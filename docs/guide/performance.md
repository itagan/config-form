# 性能基线与大表单

ConfigForm 为每个字段创建独立的 `ConfigFormItem`，根组件只负责编排。单字段输入沿路径浅拷贝 model，不会深拷贝整份数据；动态配置仍会在相关组件更新时同步求值，因此业务回调应保持轻量、无副作用。

## 可重复基线

仓库提供 200 个 Element Input 的本地基线：

```bash
pnpm test:performance
```

测试记录首次挂载和一次中部字段更新的耗时，并验证 DOM 数量、不可变写回和目标字段结果。时间只用于同一机器、相邻版本之间比较；测试中的宽松上限用于捕获数量级退化，不代表浏览器 SLA。

## 大表单建议

- 优先按业务步骤拆分表单，只挂载当前步骤真正需要的字段。
- `visible: false` 会卸载整个字段，可减少 DOM 和校验规模。
- 动态 props/options 回调不要创建大型临时结构；稳定数据尽量复用引用。
- 页面多路径更新一次替换父级 model；字段上下文中使用 `updateModel`，避免拆成多个异步任务。
- 数百个复杂选择器、日期组件或上传组件应按实际页面建立专用基线，不能用 Input 基线推断。

字段数组、虚拟化和折叠区块没有被默认塞进核心组件：它们会改变校验、焦点和挂载语义，应在出现明确业务场景和性能数据后再设计协议。
